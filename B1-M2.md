## Capability and entry points

`createOfflineMeasurementConsumer(measurementDb, {clock})` takes an explicit
separate local measurement database with atomic `batch`, not a trading env or
binding. `ingest(wire, {receivedAt})` accepts bounded M1 **wire strings** only.
There is no transport implementation, Worker entry point, network, schema
initialization, trading DB fallback, archive, reporting mutation or activation.

Apply historical migrations 0001–0003 unchanged to an empty local database,
then `0004_measurement_ingress.sql` and `0005_measurement_ingress_recovery.sql`. The existing B1 schema/codec
version 4 is intentionally unchanged; the additive tables do not reinterpret
historical B1 evidence. This migration has not been executed on any cloud DB.

## Durable ingestion

Before writes, validate bounded data-only JSON, exact envelope shape, M1 version
and namespace, measurement-only flags, semantic key, SHA-256 payload digest and
derived event ID. Use M1's canonical tagged representation and its original
occurrence/observation clocks to recompute identity; preparation time remains
outside identity. Reject invalid/future clocks, inconsistent lifecycle identity,
counterfeit census, and trading-use claims. No clock is synthesized for missing
observations. Null and unavailable clocks are distinguished by a receipt bitmask.

Receipts store metadata only, not full wire or duplicate large payloads.
The first receipt's receipt/processing-start times remain immutable across retries.
A separate durable availability fence records first confirmed ingestion after the
evidence transaction succeeds; a missing fence means analytically unavailable.
Same identity/digest succeeds idempotently; semantic-key/event-ID conflicts fail
without overwriting. SQL constraints and a pre-insert conflict trigger protect
concurrent writers, in addition to the application check.

Decision-cycle records use the existing B1 writer, codecs, identities, manifests,
definitions, pins and dependency representation. Its atomic batch includes the
receipt. No census-only fallback is claimed as complete cycle ingestion.
Evaluation sidecars validate their exact census against the decision evidence
and reuse the B1 decision store; they do not add another copy of full evidence.
An evaluation sidecar before its cycle returns `DEPENDENCY_PENDING`, retryable,
`durable:false`. The offline caller must retain/retry it; M2 has no Queue or
durable pending-message lane. This is explicit, not successful ingestion.

Official/lifecycle/confirmation/capture-gap facts and receipts commit together.
Fact payloads use the existing compressed evidence codec; this preserves the
full captured persistence result, trigger details, link and unavailable values.
Official creation may precede its cycle, so its immutable fact includes the
captured decision snapshot rather than depending on an absent decision row.
That independent durability has a measured payload cost. No full wire is kept
in a receipt/status row. A captured gap's original `durable:false` stays intact;
successful local ingestion proves only that this fact is now in the local DB.

## Lifecycle projection and recovery

Facts, not mutable projections, are historical truth. Projection rebuild reads
only immutable facts joined to their first confirmed durable-availability fences.
It retains creation identity/time/frame/direction/levels, observed milestone
times, Primary ownership, confirmation link/persistence, and persistence
failure diagnostics. Unknown fields remain null/partial. Confirmation identity
is not promoted to an Official, and a failed performance write does not create
successful trading persistence. Explicitly successful lifecycle persistence may
establish status even when creation is delivered later.

TP1 remains nonterminal. TP2, SL and expiry establish their observed terminal
state. The collector-compatible SL status is `sl`; the immutable fact preserves
the original Signal-object `stopped` value. The unchanged performance writer
uses its captured event-occurrence operand for `closed_at`, not necessarily the
Signal object's later `closedAt`. The projection records that explicit closure
basis and separately preserves `observedClosedAt`. No missing occurrence time
is invented. A local oracle test verifies this mapping against unchanged M1
persistence with distinct event and Signal-closing clocks. A successful attempt
returning a different already-terminal persistence status does not apply the
attempted event as a new persisted state.
No order is invented from ingestion order; sorting event IDs only stabilizes
encoding. Conflicting creation fields, incompatible terminal states, or TP1
after captured terminal closure produce `CONFLICT` and no usable status/closure.
This projection does not re-reduce barrier ordering: Quality Window V2 and
TP1-first outcome evidence/reduction remain unchanged.

Fact/receipt writes are atomic. Projection is a recoverable subsequent cache
write. Failure returns durable accepted ingestion with `projectionStatus:PENDING`
and a capture-gap diagnostic, rather than rolling back/denying an accepted fact.
Duplicate ingestion attempts rebuild the projection. A rebuild validates its
post-write count/digest and detects races. Work is limited to 4096 facts per
subject per rebuild invocation; exceeding this is an explicit pending projection,
**not** a correction-count/admission/lifetime-retention policy. No fact is dropped.
M5 will need a broader bounded resource/recovery contract.

`collectMeasurementFromProjection` has no trading-table query or fallback. It
selects only durably ingested cycles available by `asOf`, and uses a projection
only if all current subject facts are represented, it is available by `asOf`,
and its integrity status is COMPLETE. Officials lacking that safe boundary are
deferred without changing processing state or writing outcomes; the collector
reports their deferred count and an explicit lifecycle-pending gap. Future/stale/unavailable projection state cannot be
substituted for historical truth. A cache with later facts is conservatively
unavailable to earlier-as-of collection; M2 does not implement historical
projection queries. The existing collector entry point is preserved for existing
baseline tests/callers. Collector folds, reducers, codecs, final/dependency
validation and reference semantics are reused.

  every current immutable fact and no canonical decision conflict. Missing,
  partial, stale or failed projections leave work/cursors intact. The exact SL

  then measures only through the captured terminal boundary.
* R2: Each existing B1 evaluation ID binds once to the SHA-256 digest of its
  complete canonical decision. Cycle, census and Official copies share this
  binding. Application preflight catches changed census before the historical
  writer rejects it; an in-transaction trigger guards concurrent first arrivals.

  validated before writes. Codec tags must have exact supported shapes. Clock

  Contextual nonfinite numbers remain lossless where the codec already supports
  them; they are never admitted as valid availability/occurrence clocks.
* R4: Receipt processing start is distinct from confirmed durable availability.
  The recovery row is created atomically with evidence, initially unfenced.
  After confirmed commit a clock is sampled and its first value is durably fenced.
  Failure to publish that fence leaves evidence unavailable to analysis until
  replay repairs it. Replays never move an established first-ingestion fence.
  Existing pre-0005 local receipts are not guessed/backdated; explicit replay is

* R5: Confirmed evidence commit remains accepted if subsequent verification or

  mislabeled as a permanently malformed envelope or definitely nondurable.
  A failed validated receipt lookup is also retryable with unknown durability;
  it cannot prove that an earlier delivery was never accepted.
* R6: The existing writer's processing-capacity gaps are retained in recovery
  state and surfaced with accepted census/evidence. Replaying the immutable
  packet retries missing initialization without overwriting active/finalized
  subjects or changing the existing 4032-subject / 24 MiB budget.

The recovery processing status describes initialization only, not completion
of outcomes/reduction. CURRENT is not a claim of complete research evidence.

The offline caller must retain envelopes requiring replay; these recovery rows

The collector never falls back to trading tables.

## Final R1/R2 failure-path remediation

Validated canonical contradictions retain the evaluation and original Official
binding identity and synchronously suspend that subject before conflict-handler
reads. Known contradictions are handled first; no second binding lookup is
required. The durable PENDING intent is written before the richer immutable
marker. Failed intent storage retains nondurable pending state, requiring replay
of the rejected packet after process loss. Duplicate cycle/creation ingestion
cannot report a healthy projection while that local suspension exists.

Collector selection and projection rebuilding capture a subject generation.
Suspension invalidates it; clearing local pending after a confirmed durable intent
never makes an escaped old generation valid again. Live generation leases and pending subjects are bounded at 4,032
subjects; exhaustion fails closed, following the existing capability policy.
Leases are released on every completion/failure path; successfully reconciled
subjects do not accumulate historical generation entries. Escaped checks retain
their invalid token even when the registry entry is removed.
Previously committed valid evidence is preserved.

The original boolean/symbol admission contract was bypassable and has been
replaced by the owned offline adapter contract below. No public flag or copied
property now grants admission.

This guards collector outcome/barrier/checkpoint writes, finalized windows,
final packages, processing-state/cursor updates, and projection publication.
Adversarial tests pause two dispatched batches after the old capability check,
fail intent storage, and resume them before/after successful reconciliation.
They also suspend after SQL mutation but before COMMIT, exercise healthy same
subject collectors, and allow unrelated candidate work while an Official batch
is held. All subject outcome, state, and final-result snapshots must remain
unchanged for rejected stale work. No schema migration is required; 0001–0006
and the existing branch CI trigger remain unchanged.

## Trusted offline adapter and stable lifecycle identity

`measurement-adapter.js` is the actual supported M2 adapter implementation;
the M2 SQLite fixture constructs it without a stronger fixture-only fence.
`createOfflineSqliteMeasurementAdapter(nativeDatabaseSync)` admits a native
offline SQLite database using captured native prepare/exec methods and native
receiver checks. Node SQLite is imported only when that offline factory is
called. There is no Worker environment, remote D1, or network adapter admission.

Module-private WeakMaps register exact adapter, statement, and generation-lease
identities. The lifecycle registry is established at construction and keyed by
the native database identity. Repeated construction for that database shares
the same registry. Frozen public adapters and read-only registry views expose
neither native engine authority nor mutable suspension/generation maps.
Copying, spreading, inheriting, or advertising `measurementCommitChecks: true`
does not register a new adapter. Consumer construction, projection rebuilding,
and M2 collection reject those objects before subject writes.

`wrapOfflineMeasurementAdapter(registeredAdapter, options)` is the explicit
supported wrapper mechanism. It shares the original database/registry even
before the first lifecycle call. Read decorators and optional instrumentation
hooks are supported; replacing the batch implementation is rejected. Hooks
receive frozen SQL/value snapshots, not private transaction descriptors.
Prepared mutations always use the owned native engine. Different native
databases retain independent registries.

`commitMeasurement` accepts only privately registered leases and statements
belonging to that adapter's database. For protected Official collection and
projection publication it owns BEGIN, checks before mutations, the mutations,
the final checks, and COMMIT. The last check and synchronous native COMMIT have
no intervening await or caller hook. Suspension invalidates captured signal and
evaluation generations, even after durable reconciliation clears pending state.
An invalid check rolls back the entire transaction. An adapter cannot omit a
callback or substitute a no-op check and still commit protected work.

This uses native SQLite transaction exclusivity, not a global application work
queue. Normal transactions are synchronous; test instrumentation can pause a
transaction, in which case another transaction on that database fails retryably
rather than waits or deadlocks. A paused pre-dispatch subject does not prevent
unrelated subjects from committing; a paused native transaction holds SQLite's
ordinary database transaction boundary. Independent databases continue in both
cases. No new global serialization or retry loop is introduced.

SQL-trigger-discovered canonical conflict immediately suspends the attempted
subject and validated evaluation before any fallible binding enrichment. The
evaluation fence also blocks the canonical Official when the rejected packet
names a different signal. A failed lookup leaves duplicate responses PENDING,
rebuild publication unavailable, and collection deferred. Intent persistence
precedes richer conflict-marker processing. Confirmed intent permits local
pending cleanup but cannot revive escaped generations. Failed intent retains
truthful nondurable pending; deterministic packet replay reconciles durable
quarantine/conflict once, without duplicate immutable facts.

Nondurable suspension lasts for this database capability's process lifetime.
A future transport integration must retain/replay rejected packets and reconcile
unresolved contradictions before analytic use after process loss. There is no
M3 transport implementation or durability claim here. Future adapter engines
require an owned check-through-commit implementation and explicit registration;
public booleans or documented callback conventions are insufficient.

Retained pending signal/evaluation sets each cap at 4,032; live generation
tokens cap at 8,064. Exhaustion fails closed. Released leases and successful
reconciliation remove registry entries; escaped invalid tokens remain invalid.
Projection evaluation lookup is bounded by the existing `maxFacts` work limit.
Four numerical diagnostic counters are retained per database. Other identity
registries are WeakMaps.

## Final Candidate and rebuild dependency fences

evaluations and skips live-suspended evaluations during bounded selection.
Every Candidate mutation, including market blocks, outcomes, windows, final
results and processing-state updates, uses the registered evaluation lease.
The native check verifies both the live generation and durable quarantine in
the same owned transaction immediately before synchronous COMMIT. A suspended
generation stays invalid after reconciliation, while unrelated evaluations
continue without an application-wide lock.

stale publication; a post-commit verification prevents returning a stale

rebuilds complete. No schema or migration change was needed.

## Final projection return consistency

M2-FINAL-RETURN-04 was reproduced on c46af210: a delayed final projection read
could retain a one-fact COMPLETE/active snapshot while public SL then TP2
ingestion made the authoritative three-fact projection CONFLICT. The old return
and duplicate consumer could still claim COMPLETE/CURRENT. The collector's
accepted write fences continued to defer that Official.

After its last awaited projection read, rebuilding now validates the snapshot
through the registered adapter's owned native synchronous read transaction.
It checks lifecycle revision, current projection revision/digest/status/count/
availability, captured fact availability/count, canonical conflict/quarantine,
the complete binding set, live suspension, and the rebuild's generation leases.
Read decorators cannot provide these validation rows or insert asynchronous
work into this operation. Any mismatch throws the existing safe raced/pending
error rather than constructing a newer projection in memory.

A private WeakMap associates each returned projection with its immutable
validation metadata and original database capability. Immediately after
awaiting rebuild, the consumer repeats native validation before constructing
COMPLETE/CURRENT-related response status. Stale duplicate responses become
retryable PENDING while confirmed receipt durability remains truthful. Copies
and independent database capabilities cannot reuse a return snapshot. This
metadata follows the returned object's lifetime and retains no generation
leases; healthy lease/token cleanup remains unchanged.

The consistency point is the final synchronous native read transaction after
the last awaited read (or, for consumer responses, after awaiting rebuild).
The relevant authoritative reads share one SQLite snapshot; local suspension
checks and response construction have no intervening await or instrumentation
hook. No claim is made that status stays current after return begins. A later
change requires another validation/rebuild. There is no application-wide lock,
new migration, Candidate-fence change, or publication redesign.

M2-FINAL-STATUS-05 (Candidate rejection counted as deferred Official) and
M2-FINAL-RESOURCE-03 (default SQL diagnostic log) remain unchanged non-blocking
follow-ups, together with the previously recorded M2-P1, M1-CPU, and M1-R3.
