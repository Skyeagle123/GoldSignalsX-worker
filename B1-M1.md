# B1 M1 — offline measurement producer

Baseline: `d95d804baf447e32be59481b77690bf171e7debb`, tree
`b9a30627ee14c6e3f0fc2c8da781192745ab7b01`.

M1 is an offline shadow path. It does not replace the existing B1 collector,
retention or reporting path. There is no Queue adapter, binding, D1 migration,
R2 access, new Worker or Production activation. The legacy capture wrapper
continues to persist the same records using the extracted preparation function.
No Signal Engine, Exposure, Risk, News/Calendar or Telegram policy changes.

## Gate and integration

`B1_PRODUCER_CAPTURE_ENABLED` is OFF unless its value is exactly `1` after
whitespace normalization. No deployment configuration was added.

The completed/error cycle journal is observed after existing trading persistence
and telemetry. Confirmation fact references are staged after successful link writes.
Lifecycle fact references are staged after existing lifecycle/Telegram persistence,
including the invalid-market expiry path. They distinguish lifecycle observations
from independent performance persistence success/failure and assert no new
barrier ordering quality. Missing observation timestamps remain explicitly null
or unavailable; no new engine clock is substituted.

Only small observed references and one capture-time scalar are staged inside
the timeframe loop. A cycle-wide timer dispatch runs after the trading cycle
settles and its promise continuations have run. The deferred job constructs
facts and performs all producer copying, freezing, canonicalization, hashing,
serialization and offline delivery. This timer is not a durable handoff.

Only tests install an offline transport with `installOfflineMeasurementProducer`.
An enabled gate without that injection reports `TRANSPORT_UNAVAILABLE`; it does
not activate a cloud transport. Scheduling and delivery results never enter the
trading return value. Existing trading exceptions and cancellation behavior are
preserved. The pre-completion path still has small observation bookkeeping;
deferred preparation consumes CPU after completion and is not a Production
latency or isolate CPU guarantee.

## Envelope v1

Kinds: `DECISION_CYCLE`, `EVALUATION_CENSUS`, `OFFICIAL_CREATION`,
`CONFIRMATION_LINK`, `LIFECYCLE_FACT`, `CAPTURE_GAP`.

Every packet contains a frozen envelope, its canonical tagged-JSON wire string,
wire/payload/header byte counts and a future-fragmentation indicator. Tagged
undefined/nonfinite values use the established evidence convention. Census
sidecars include the existing compact census and exact decision evidence.
Cycle packets contain the unchanged prepared records, pins and links; raw input
is present, not a reference to transient trading memory. Sidecars repeat some
cycle data for this offline interface; they are not additional statistical
subjects or instructions to duplicate stored evidence.

Semantic IDs are unchanged. `semanticKey` is canonical JSON of namespace, kind
and semantic ID. `payloadDigest` is SHA-256 of canonical
`{clocks:{occurredAt,observedAt},payload}`. `eventId` is `m1:` plus SHA-256 of
canonical `[namespace,kind,semanticId,payloadDigest]`. Preparation time is excluded
from identity. A conflicting observed clock is therefore detectable too.
The first capture timestamp is reused for retries of the same journal without
mutating it. Transport retries reuse the frozen packet.

## Enforced preparation bounds

- Cycle input: at most 8 MiB of charged scalar/key bytes, 200,000 nodes, depth 24.
- Fact input: at most 64 KiB of charged scalar/key bytes; same node/depth ceilings.
- Individual cycle packet and entire cycle batch: at most 2 MiB of wire data.
- Individual standalone fact: at most 64 KiB of wire data.
- Two cycle capacity slots reserved independently from fourteen fact slots.
- Delivery timeout: at most 1,000 ms; tests may select a shorter timeout.
- Uncooperative timed-out sends retain their class capacity until they settle.
- Diagnostic ring: 32 entries; identifiers exceeding 1,024 UTF-8 bytes are
  unavailable in this bounded diagnostic, not silently truncated evidence.
- Offline recorder: at most 128 packets / 16 MiB, with explicit capacity failure.

Dense arrays and enumerable data-only objects are required. Sparse slots,
accessors, extra array properties and other lossy shapes fail before their
values are copied or canonicalized. Length, keys and nodes are charged before
materializing their children. Direct envelope construction uses the same input
preflight. These checks do not execute property getters on supported plain
evidence. Charged input bytes are not a bound on physical heap usage. Tests/measurements
report local memory deltas. These are workload bounds, not universal CPU-duration
or cloud-memory guarantees. All overflows produce an explicit local capture gap;
no selected field is removed to make an envelope fit. Full evidence need not fit
these M1 bounds; failure is truthful and trading remains fail-open.

More than 60,000 wire bytes indicates a future M3 fragmentation requirement.
M1 implements no fragmentation or multipart delivery. A partially accepted mock
batch does not establish complete capture. The mock is memory-only: all statuses
and diagnostics state `durable:false`. `whenIdle()` exists for offline tests;
trading never awaits it. A scheduler callback that never runs is not a durable
handoff. Queue durability and incident preservation belong to later phases.

## Validation and measurement

Run locally:

```sh
node --test test-b1-*.mjs test-news.mjs test-reliability.mjs test-risk-budget.mjs test-risk-sizing.mjs test-signals-security.mjs
node scripts/measure-b1-m1.mjs /absolute/local/path/m1-measurements.json
```

The focused suite loads the exact baseline Worker and capture module from git.
It compares full trading results, KV writes, production rows, Exposure decisions,
cancellations and offline Telegram event records across normal/failure cases.
It also compares every captured database record with deterministic JavaScript
and SQLite clocks. The historical 280-fixture engine differential remains intact.

The existing Reliability HTTP fixture used real runtime time against fixed
historical caches and failed on the baseline. Its clock is now aligned for that
request only; no health runtime behavior or expected result changed.

The benchmark uses complete representative/heavy-valid seven-frame profiles,
non-null News/Calendar and observed Exposure context. It includes active ownership,
early Engine rejection, census/technical candidate evidence, Official creation,
confirmation, actual locally persisted lifecycle results and a nondurable gap.
Five warmups and forty measured samples/profile produce median/p95/maximum for
copy/freeze, reused capture preparation, envelope canonicalization, hashing,
serialization and total elapsed preparation, plus process CPU time. Process CPU
includes runtime/GC/native hashing work and is not Cloudflare isolate CPU.
Reused capture preparation includes its own
manifest canonicalization/hashing; that work is not omitted from total cost.
Memory deltas include GC and can be negative. Local maxima are not universal
valid payload maxima or Production performance guarantees.

The paired timing sample compares exact-baseline and enabled trading completion
over forty local cycles, then separately times completion to producer idle.
Its difference contains runtime noise and is not isolated instruction CPU;
the deferred interval includes timer and offline delivery costs. The active-5m
TP1 regression advances the clock by 2 ms when producer work begins with an
initial 19,999 ms quote age; baseline, OFF and ON all retain six confirmations.
