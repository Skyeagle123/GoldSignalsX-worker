## Boundary

M3 is a disconnected offline library. No Trading Worker, M1 producer, M2
consumer, collector, lifecycle, trusted adapter, schema, migration, deployment
configuration or CI workflow is changed. Existing M1 deferred scheduling remains
the activation boundary. An offline harness may explicitly inject the new
transport into the existing producer. It is never installed by the worker.

```
accepted M1 packet.wire -> fragment frames -> bounded mock staging
-> verified original packet.wire -> public M2 consumer.ingest
```

Only the supported public consumer is invoked. M3 never prepares SQL, writes M2
tables, accepts partial logical evidence, alters clocks, or modifies semantic
identity. The existing M1 envelope builder verifies framing identity; full public M2
validation is applied after assembly before consumer delivery. M2 still controls immutable evidence, canonical binding, conflict,
quarantine, trusted transactions, generations, projections and acknowledgement.

## Framing

`measurement-transport-fragment.js` exports fragmentation, validation and
assembly. `fragmentMeasurementPacket(packet, {receivedAt})` emits canonical JSON
strings. Each application envelope is **at most 60,000 UTF-8 bytes**. Version 1
uses 42,000 raw bytes per fragment, canonical base64, and a bounded header. The
complete event limit is the accepted M1 2 MiB wire bound, permitting up to 50
fragments. The largest measured fixture is not treated as a universal maximum.
All original UTF-8 bytes are retained, including characters spanning chunks.

Each frame has exactly these fields:

| Field | Meaning |
|---|---|
| version / namespace | `1` / `goldsignalsx:b1:m3` |
| eventId / eventKind | Original M1 event identity / kind |
| payloadDigest | Original canonical logical payload digest |
| wireDigest | SHA-256 of the entire original serialized wire |
| totalBytes | Complete UTF-8 length, 1 through 2 MiB |
| count / ordinal | Exact fixed-chunk geometry / zero-based ordinal |
| fragmentBytes / fragmentDigest | Exact raw chunk length / SHA-256 |
| fragmentId | Deterministic identity described below |
| data | Canonical base64 of the raw chunk |

Fragment identity is `m3:` plus the SHA-256 of the canonical array
`[namespace, version, eventId, payloadDigest, count, ordinal]`. Retries, arrival
order and receipt clocks do not enter identity. Preparation time does not enter
the identity formula. A changed preparation field may change serialized length
and thus the declared count; count is explicitly part of identity. Exact-wire
comparison also uses wireDigest: different bytes under the same M1 event ID are
an integrity conflict, including otherwise equivalent changed preparation data.
Different payloads under a semantic key retain their M1 event IDs and go through
M2's canonical contradiction handling, rather than overwriting prior evidence.

Frame length is bounded before parsing or base64 decoding. The validator checks
the exact object shape, version, namespace, identity syntax, kind, digest syntax,
total bound, exact count geometry, ordinal range, exact chunk length, canonical
base64, fragment digest and identity. Sparse or enormous declarations cannot
cause an array allocation. A complete buffer is allocated only after every
actual fragment has been individually verified and its actual length summed.
Full wire length, digest, strict UTF-8, full M2 wire validation and manifest
identity must all match before consumer delivery.

## Bounded mock state and delivery

`measurement-transport-multipart.js` exports private-store factories and
`createOfflineMultipartTransport({consumer, store, clock, ...policy})`. A copied
store object cannot gain admission. This is transport bookkeeping, and does not
replace the independently trusted M2 database capability.

| Resource | Default | Allowed maximum |
|---|---:|---:|
| Retained event records, including terminal records | 32 | 64 |
| Retained event fragment envelope bytes | 16 MiB | 16 MiB |
| Poison input records | 64 | 64 |
| Poison original input bytes | 4 MiB | 16 MiB |
| Simultaneous receive/validation operations | 64 | 64 |
| Simultaneous packet framing operations | 16 | 16 |
| Attempts in a delivery/replay cycle | 3 | 16 |
| Explicit replay cycles per retained record | 4 | 16 |
| Retry delay | 1 second | 1 day |
| Modeled transport retention | 14 days | 14 days |

Event DLQ entries are retained event records and share their event/byte bounds;
poison entries use the separate poison bounds. Headers, leases and retry metadata
are bounded per retained record. Full event buffers and asynchronous digest
buffers are temporary overhead beyond staged envelope bytes; staging accounting
does not claim to measure the JavaScript heap. Limits reject admission explicitly
with `CAPACITY_PENDING` / `OFFLINE_CAPACITY_EXCEEDED`. A bounded rejected poison
input that cannot fit returns `originalRetained:false`; oversized input is not
silently truncated or claimed preserved. Terminal records are retained until
explicit owner `discard`, which updates discarded-byte accounting. Discard is
denied during admission/delivery and for nonterminal records.

Frames can arrive in any order or interleave across events. A verified ordinal
is stored once. Identical duplicates add no staging bytes. Conflicting bytes or
manifests enter the bounded poison DLQ and do not replace the original event.
Incomplete status is `STAGING`, with exact `missingOrdinals`. No incomplete
event is sent to M2. Duplicate fragments after acknowledgement return an
explicitly historical receipt (`consumerResultHistorical:true`). A redelivered
full packet (`send`) or explicit replay enters M2 again; M2 decides DUPLICATE,
pending or conflict against its current authoritative state.

There is one in-flight promise per event, shared by runtimes using the same
retained store. Concurrent final fragments, replay and normal delivery join that
promise. Unrelated events have no application-wide work lock and can progress
while another event awaits acknowledgement. Native SQLite transaction exclusivity
continues to belong to M2. This library adds no database lock or global serializer.

## Retry, DLQ and replay

`consumerResult` is the exact bounded M2 response, including its receipt
durability and projection/processing status. Transport itself always reports
`durable:false`. `ACKNOWLEDGED` requires a confirmed durable ACCEPTED/DUPLICATE
receipt with no pending projection/processing or retry flag. Producer-compatible
`send` reports `OFFLINE_ACCEPTED` / `DUPLICATE` only for that state. PENDING,
DEPENDENCY_PENDING, DURABILITY_UNKNOWN and unresolved integrity conflict remain
explicit and are never transformed into generic success.

| Classification | Policy |
|---|---|
| ACKNOWLEDGED | Preserve receipt; duplicates/replay remain idempotent through M2 |
| RETRYABLE | Explicit retry after deterministic due time |
| DEPENDENCY_PENDING | Preserve evidence and M2 dependency state; retry |
| DURABILITY_UNKNOWN | Preserve uncertainty; retry same bytes/identity |
| INTEGRITY_CONFLICT | Preserve M2 conflict; retry only if M2 says retryable |
| PERMANENT_MALFORMED | Mock DLQ immediately, no consumer ingestion |

No background timers or automatic network delivery exist. `retry(eventId)` is
an explicit offline harness operation. Exceptions from M2 become retryable
unknown acknowledgement, rather than false success. Deterministic exhaustion
or a permanent result moves the retained event to `DLQ`. Attempt count,
cycle count, replay count, original frames, first/last failure clocks, reason,
classification and last M2 result are retained. `replay(eventId)` explicitly
starts a bounded new delivery cycle from the same complete frames; it never
mints a semantic event or alters occurrence/observation clocks. Poison replay
uses the exact retained poison wire and cannot promote malformed input to valid
evidence. DLQ is bounded diagnostic/retry state, not permanent archival storage.

## Expiry and restart

First-fragment receipt establishes `expiresAt`. Duplicate arrival and ordinary
retry do not extend it while delivery is incomplete or unacknowledged. The harness supplies a deterministic nonnegative safe
integer clock and is responsible for a coherent timeline. At expiry, incomplete
records become `EXPIRED_INCOMPLETE`, retain truthful missing/byte accounting,
and cannot complete or replay from their missing subset. Complete retry records
move to DLQ with `TRANSPORT_EXPIRED`. Explicit replay of a retained complete DLQ
event starts a new modeled retention interval, preserving evidence clocks.
Confirmed acknowledgement remains a historical receipt, not a promise of eternal
capture. No permanent lossless-capture guarantee exists after expiry/discard.

`createVolatileTransportStore` is lost with its owning object. The deliberately
named `createMockDurableTransportStore` survives a **simulated runtime restart
only because the test harness retains that object**. Both are in-memory and
neither survives process/object loss. This is not real Queue or durable storage.
`crash()` invalidates only the crashed runtime's active delivery leases and releases its receive/send admission tokens exactly once. Other live runtimes retain their own charges; late finally blocks cannot double-decrement them. Receive/send ownership sets are bounded by the shared 64/16 admission limits. An
attempt lost before acknowledgement becomes DURABILITY_UNKNOWN/retry pending.
An obsolete runtime cannot later overwrite the restarted runtime's ledger.
If M2 committed before transport acknowledgement was lost, redelivery asks M2
again and observes DUPLICATE. Partial staging, retry, DLQ transition, replay and
pre-acknowledgement crash points are tested explicitly. Hooks are offline fault
injection points, not hooks inside M2's trusted transaction or final return.

## Census and detailed evidence

Every accepted M1 envelope kind has its own independent transport manifest and
record. A missing Official/detail envelope does not discard a captured census.
An early census awaiting its canonical cycle retains DEPENDENCY_PENDING and its
original fragments. M3 does not weaken M2 dependency closure or advertise that
pending census as durably ingested. Once the canonical cycle is accepted, retry
can capture the census independently of subsequently missing detail envelopes.

is ENGINE_REJECTED, levels are NOT_COMPUTED_BY_ENGINE and unavailable, Engine
result/identity match timeframe/evaluation time, and the versioned ordered Engine
gate evidence contains a real failed gate. Officials and contradictory or
malformed non-directional evidence remain rejected. Canonical identities/digests
and all existing M2 fences remain enforced. Existing computed-level eligibility
excludes these census records from directional processing without losing the
evaluation denominator. The actual flat-bar Worker/M1 path persists seven such
evaluations exactly once through public M2 ingestion.

The original 182,996-byte fixture was unfinalized: it labeled its non-directional
rejection OFFICIAL_PERSISTENCE_FAILED because both compared IDs were undefined.
The regression preserves those original bytes and verifies rejection rather than
loosening the contract. Setting its observation's failedOfficialId to null (the
normal finalization default) produces truthful ENGINE_REJECTED evidence, still
five fragments, byte-identical reassembly and durable census acceptance. This
minimal fixture correction changes the complete wire/digest; no claim is made
that the old mislabeled bytes are now accepted.

M3-EXPIRY-02 evaluates the existing deadline before replay metadata changes and
again after the optional awaited replay hook. An elapsed incomplete record cannot
revive, whether replay, sweep or late-fragment receipt detects expiry first;
accounting transitions once. A confirmed complete event redelivery begins a new
attempt interval and still invokes M2 idempotency after the old transport deadline.
M3-RESTART-03 uses private runtime-owned admission tokens; crash and finally
release the same tokens idempotently. Multiple live runtimes are tested separately.
No global work lock, schema change, cloud capability or trading activation added.
